# `brico-app` bindings

Generated SpacetimeDB 2.x client bindings for the `brico-app` module (`backend/brico-module/`),
imported as `@brico/bindings/brico-app`. Generated output — do not hand-edit. Regenerate with:

```sh
npm run generate --prefix backend/brico-module/spacetimedb
```

(`backend/brico-module` is deliberately not a workspace member, hence `--prefix` rather than
`--workspace`.)

## What is and isn't here

`account`, `linked_integration`, `service_principal`, `saved_craft_filter` and
`craft_filter_watch` are **private** tables — the CLI reports `Skipping private tables during
codegen` and no client can subscribe to them. Clients read through views instead, so the only
table accessors on `DbConnection` are:

| accessor | SQL name | contents |
| --- | --- | --- |
| `conn.db.myAccount` | `my_account` | the caller's own `account` row, or nothing |
| `conn.db.myLinkedIntegration` | `my_linked_integration` | the caller's own integration links |
| `conn.db.mySavedCraftFilter` | `my_saved_craft_filter` | the caller's own saved craft filters, tombstoned ones included |
| `conn.db.myCraftFilterWatch` | `my_craft_filter_watch` | the caller's own filter watches, tombstoned ones included |
| `conn.db.allAccount` | `all_account` | every `account` row — empty unless the caller is a registered service principal |
| `conn.db.allLinkedIntegration` | `all_linked_integration` | ditto for integration links |
| `conn.db.allSavedCraftFilter` | `all_saved_craft_filter` | ditto for saved craft filters |
| `conn.db.allCraftFilterWatch` | `all_craft_filter_watch` | ditto for filter watches |

`my_*` views filter by `ctx.sender`; `all_*` views are the same kind of query view but with a
constant `service_principal`-membership predicate instead of a per-row one. That distinction is
invisible from here — a client cannot tell a view from a table.

Row types (`Account`, `LinkedIntegration`, `ServicePrincipal`, `SavedCraftFilter`,
`CraftFilterWatch`) live in `@brico/bindings/brico-app/types`; reducer arg types in
`@brico/bindings/brico-app/types/reducers`. Filter/watch sync reducers:
`conn.reducers.upsertSavedCraftFilter({...})`, `deleteSavedCraftFilter({...})`,
`upsertCraftFilterWatch({...})`, `deleteCraftFilterWatch({...})` — each single-params-object, same
as `setDisplayName`.

## `ensureAccount()` is required

No `account` row exists until a client calls it — connecting does not create one. Call
`conn.reducers.ensureAccount({})` once after the connection opens; it is idempotent. Note the
**`{}` is required** — an argumentless reducer still generates a one-parameter accessor, so
`ensureAccount()` is a type error. `brico-bot` must *not* call it: service principals are refused,
since a trusted reader is not a user.

## Two naming gotchas versus `../prism`

- **Accessors are camelCase here, snake_case in `prism`.** `conn.db.myAccount` /
  `reducers.setDisplayName`, not `conn.db.my_account`. `prism` is a Rust module generated by an
  older CLI; this one is a TS module generated by CLI 2.9. SQL strings are still snake_case
  (`SELECT * FROM my_account`), and `tables.myAccount` is the query-builder handle to pass to
  `.subscribe([...])`.
- **Reducers take a single params object**, e.g. `conn.reducers.setDisplayName({ displayName })`.

`types.ts` also emits empty `t.object("MyAccount", {})` placeholders for each view. Those are a
codegen artifact, not the row shape — use `Account` / `LinkedIntegration`, or the default export of
the matching `*_table.ts`.
